Behind the scenes

Bug Sweep Day

Kirk26 November 20268 min read

Yesterday's v0.3.0 brought every VorT2x app together in one window. Before building anything new on top of it, I went through all of VorT2x with a fine-tooth comb: the fan and power daemons, the installer and updater, the AirDrop and Quick Share receivers, the kernel drivers and the background services. Anything that could leave your Mac in a bad state, hang, lose a file or wake the CPU for no reason went on the list.

Today all of it is fixed in VorT2x v0.3.1. Some fixes are for every T2 Mac, some for one model. Here's the whole list, grouped by what it means for you.

Fans that always let go

When VorT2x controls your fans, it switches the SMC (the chip that runs the fans) into manual mode. The SMC stays in that mode until someone tells it otherwise. So if the fan daemon stopped, crashed or was uninstalled, your fans could stay stuck at whatever speed they last had, fast or slow. That's fixed from every direction:

  • Fans go back to the Mac whenever the daemon stops. A normal stop, a shutdown, an uninstall, a crash or even a forced kill: every way out now hands the fans back to the SMC. It tries every fan and keeps retrying until all of them are released. The SMC driver itself also lets go of the fans on shutdown and when it's unloaded.
  • No temperature reading no longer means slow fans. If the daemon can't read a temperature, it now gives the fans back to the SMC instead of setting them to minimum, and takes them back once readings return. If readings fail for about ten seconds in a row, the daemon restarts itself and finds the sensors again, even if they moved.
  • Short glitches stay short. One failed reading no longer makes the daemon retry in a tight loop or restart straight away; it keeps its normal pace.
  • The fan settings can't be stalled. The settings connection now has one firm deadline per request, so a misbehaving client can't hold up fan control, and the Fans page gives up after three seconds instead of freezing.
  • Only the person at the Mac can change fan settings. Changing them needs root or the user logged in at the Mac itself; an SSH login no longer counts. The same rule now applies to starting the Quick Share hotspot. Settings are saved in one step, so a crash mid-save can't leave a broken file.

A steadier iMac Pro

  • The Vega clock hold survives sleep. In v0.2.3 the iMac Pro learned to hold its graphics card back from its very top clock, which is what stops games from sending it to sleep. A GPU reset after waking could silently drop that limit. VorT2x now puts it back after every sleep, whenever the GPU wakes from its own power saving, and checks it every five seconds while the GPU is busy.
  • The 5K panel's right half keeps up. A new fix to the iMac Pro 5K display patches: when only the left half's mode or on/off state changed, the right half could be skipped. Both halves now always change together.
  • The log no longer claims "no supported dGPU" right next to the line saying the Vega clock is held.

Updates that tell the truth

  • A part that failed is no longer recorded as installed. When one piece of a step failed, for example a driver that wouldn't build for a new kernel, the step could still be marked as done, and VorT2x Update never offered it again. Now a step with a failed part counts as failed and gets retried. A new automatic test makes sure this stays fixed.
  • Kernel updates without a network work. GNOME Software and Discover can install a new kernel while offline, and then VorT2x couldn't download the source it needs to build its drivers, so that kernel booted with stock graphics, Wi-Fi and Thunderbolt drivers. Now such a kernel is marked, and about two minutes after the next boot VorT2x rebuilds its drivers in the background, without holding up your desktop.
  • No more install terminal at every login when the ACPI fix couldn't be applied. That failure is a warning again, as it was meant to be.
  • Kernel patches apply more carefully. They now need a closer match with the kernel source, and when a looser match is needed as a fallback, the installer names exactly which parts needed it.
  • Faster dependency installs: all packages go in one dnf transaction, falling back to one at a time only if that fails.
  • Updates only come from GitHub's own release tags. The updater asks GitHub directly which releases exist and checks out exactly the commit GitHub names, so nothing added to the copy on your disk can pass for a release.
  • Smaller fixes: the macOS USB script no longer stops on Macs without Touch ID, reusing the USB stick keeps the original Fedora boot menu backup, and the rescue tool no longer empties the live session's DNS settings and now reports the input drivers for each kernel.

AirDrop and Quick Share: nothing until you say yes

  • Nothing is written to your disk before you accept. Incoming files are saved under a temporary name only after you say yes, and get their real name once complete. Decline, cancel or a dropped connection, and the partial files are removed.
  • Two files with the same name never overwrite each other. The second one gets the next free name.
  • Oversized or odd offers are refused: more than 1000 files, more than your free space, or a second introduction from the same sender. Memory use per transfer is capped, and one bad accept no longer stops the whole service.
  • The AirDrop receiver grows only as data arrives, instead of trusting the size the sender claims, and only after you've accepted. Its service now runs with a memory limit and a read-only view of the system, and files always land in ~/Downloads.
  • Force Click only runs a stored command for the user who set it (if you had one, save it once again in the app), and Power Tune only accepts real device names.

Kernel drivers

  • Internal USB after sleep (every T2 Mac). The camera, keyboard, trackpad, Touch Bar and ambient light sensor all sit behind the T2 chip's internal USB. A race when a request was cancelled could free memory that was still in use, and one port that failed to wake made Linux drop every T2 USB device. Both are fixed, along with several smaller error-handling gaps.
  • A load average that tells the truth. The Sidecar driver's background thread counted as busy while it waited, adding a constant 1.0 to your load average. It now waits quietly, and backs off instead of spinning when the device reports errors.
  • Touch Bar (MacBook Pros with a Touch Bar): pressing Fn no longer does slow work in a spot where it must be fast, Fn presses during sleep are ignored instead of queued, unloading is safe, and the dimming timer is reset at most once a second.
  • Audio: a quick wake-then-sleep can no longer run leftover wake-up work into the next sleep.
  • Graphics switching (MacBook Pros with two GPUs): a busy mailbox was read as data, which could cause an endless interrupt loop or power the AMD GPU down by mistake after waking. The driver also stops reporting stale data when a read times out.
  • Smaller fixes: a failed display probe cleans up properly, an uninitialised value is gone from the SMC key cache, and CPUs stay online for s2idle sleep.

A quieter Mac at idle

Every wakeup costs a little battery and a little heat. Three services were waking up far more than they needed to:

  • Touch ID only watches the Escape key while a fingerprint check is actually running, and backs off when the sensor isn't reachable.
  • Zone Power checks an unchanged CPU limit every five seconds instead of reading every CPU's settings four times a second.
  • Force Click checks for its trackpad with one quick look instead of opening every input device once a second.

No more donation links

VorT2x builds on the work of the original authors and the wider T2 Linux community, so it won't ask you for money. The donation links are gone from every app, the dashboard and this website.

How it was checked

Every change went through the project's static checks, the Rust apps' own tests with warnings treated as errors, and a fresh build of every changed kernel driver against Fedora 45's 7.3.4 kernel with extra warnings turned on. The iMac Pro 5K patches were applied to a Fedora kernel and built, just as the installer does it. On real hardware, v0.3.1 is running on my iMac Pro (2017) and a 13-inch MacBook Pro (2020): both installed it, rebooted and came up clean.

Want to see the fan fix for yourself? Run sudo systemctl stop t2-fancontrol and listen: within a few seconds your fans should settle back to the Mac's own speed. sudo systemctl start t2-fancontrol brings VorT2x's fan curve back.

Still on the list

A few things from the review need a bigger change or more testing, so they're planned for later: building updates from a source folder that only root can change, the remaining background wakeups (Touch Bar, True Tone, the AirDrop receiver and internal USB polling), and skipping driver builds that haven't changed.

Getting it

Already running VorT2x? Open the Updates page in the VorT2x Dashboard and install v0.3.1. New installs get it straight away. Every change, with its reasoning, is in the pull request.

Found something we missed? Tell us, and it goes on the next sweep.
